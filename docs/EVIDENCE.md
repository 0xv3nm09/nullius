The hackathon publishes no numeric scoring rubric. The rows below are therefore taken from the **literal asks of the Investment Thesis track brief** and from `HACKATHON.md`'s stated review process, rather than from invented weights.

## 3 · Where the case library and results live

The house standard expects `eval_cases/` and `eval_results/`. This project has both, under different names, because they are the same artifacts:

| Standard artifact | Here | Why it qualifies |
| --- | --- | --- |
| `eval_cases/cases.yaml` | `src/propositions.ts` | One entry per proposition carrying its `falsifier` (English) and `kind` (machine form), **committed before any value exists**. The expectation therefore provably predates the run that produced the result |
| `eval_results/latest.json` | `data/snapshot.json` | Machine-written, never hand-edited. Carries `generatedAt`, the captures with their hashes, every metric with `value` and `verdict` as sibling fields, and the summary counts |
| `scripts/render_results_md.py` | `src/cli/verify.ts` | Writes `VERIFY.md` from the snapshot plus a recomputation. No figure in that report is hand-typed |

The property the standard is protecting — that a regression cannot hide — holds: `expected` and `got` are siblings on every row of `VERIFY.md`, and any divergence sets a non-zero exit code.

## 4 · The 60-second tour

Four steps, cold to convinced. Nothing here needs a key, an account or a network connection.

**1 · Read the finding (10s)** — open <https://0xv3nm09.github.io/nullius/> and read the dark band. Four of the twenty fields in NEAR's most-used public analytics endpoint do not survive an audit: `multichain_txns` is empty across all 2,307 days of chain history, `circulating_supply` has been frozen since 2025-08-27, and `active_contracts` and `deleted_accounts` each carry an unreconciled definitional break. These are the numbers a rushed thesis quotes first.

**2 · Check that the thesis reports against itself (15s)** — scroll to the verdict tiles: **5 supported · 6 unsupported · 4 data unusable.** Click T-09 and T-11: the project publishes NEAR's Nakamoto coefficient as 9, and roughly 5 once staking pools are grouped by operator name prefix — labelled as a heuristic, with its caveat rendered beside it. Then click any figure to open its provenance drawer: source URL, fetch timestamp, raw SHA-256, chain index.

**3 · Reproduce every figure yourself, offline (20s)**

```bash
git clone https://github.com/0xv3nm09/nullius && cd nullius
npm install && npm run verify:offline
# → OFFLINE: 15/15 metrics recomputed from committed captures; chain head matches; liveness not checked.
```

No `.env`, no key, no network to NEAR. The run states explicitly that receipts were not checked because no secret is configured — it does not pass silently.

**4 · Break it, and watch it fail closed (15s)**

```bash
make tamper
# → tampering T-01: 2.872662173596536 -> 12.0
# → chain broken at index 0: hash mismatch: expected d3bd2512… got e8072526…
# → exit=1   (snapshot restored automatically)
```

That is the whole argument. The provenance chain is load-bearing rather than decorative: alter one published number and verification names the index it broke at and exits non-zero.

**If you have network, one more:** `npm run verify` re-fetches from mainnet and recomputes. A figure that has moved since the capture is reported as drift with both values — a pass of the design, not a failure. The thesis is built to turn against itself without anyone editing it.

## 5 · How to verify independently

Operations a sceptic performs without our help:

| Claim | Independent check |
| --- | --- |
| The captures are the real source bytes | `curl -s https://api.nearblocks.io/v1/charts \| shasum -a 256` and compare against `sha256` for `charts` in `data/captures.json`. The source moves, so expect a difference once it has — then run `npm run verify`, which re-fetches and recomputes rather than asking you to trust the old hash |
| The published figures match the captured bytes | `npm run verify:offline` — recomputes all 15 from `data/raw/` with no network |
| The records have not been altered since publication | `npm run verify:chain` — recomputes every record hash in order |
| The falsifiers predate the values | `git log -p src/propositions.ts` — the falsifier text is committed; compare its commit against the snapshot's `generatedAt` |
| No model produced any number | `npm test` → `test/architecture.test.ts` walks the import graph and fails if `src/compute/**` touches the network, the filesystem, the clock, randomness or a model SDK. Every `prose[]` entry carries `model: null` and no digits |
| A figure traces to its code | each metric record's `computedBy` names the exact exported function, e.g. `metrics.validatorNakamoto` |
| The deployed site matches the source | rebuild from a fresh clone and compare the asset hash in `docs/index.html` against the one the live page requests |

One claim you **cannot** independently verify: the JWS receipts are HS256 under an author-held secret, so you can verify the hash chain completely but not the signatures. That limit is stated in `SYSTEM_CARD.md` and is the first roadmap item.
